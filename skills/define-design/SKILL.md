# Design brief

Read [Procedure data](../../references/procedure.md) before the task.
Read [Design format](../../references/design-format.md) for document changes.
Read [Technical terms](../../references/technical-terms.md) for skill language.

## Task

Make a design brief that records the developer selections.

## Input

- Developer instructions.
- Project instructions and available design data.
- Reference interfaces, images, and exclusions.

## Procedure

1. Read the project instructions and design data.
2. Get the audience and primary task from the developer or the project data.
3. Record the approved references and their applicable functions.
4. Record the selections to keep and the selections to prevent.
5. Compare the selections for differences that prevent the same task.
6. Get a developer decision for each such difference.
7. Record missing data as `unresolved`.
8. Put example values in a different list with the status `proposed`.
9. Write the design brief at the specified project path.
10. Show the recorded selections and missing data.

## Output

- A design brief with audience, primary task, references, selections, exclusions, and unresolved items.

## Completed task

- Each selection has a source or the status `proposed`.
- The design brief divides developer selections from example values.
